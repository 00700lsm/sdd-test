# Quickstart: 알림 창과 확인 창

설계 확인용 실행 절차이다. 구현 코드와 테스트 본문은 `tasks.md` 이후의 구현 단계에서 만든다.

관련 계약: [contracts/dialogs.md](contracts/dialogs.md)

관련 모델: [data-model.md](data-model.md)

기존 동작: [001 quickstart](../001-user-management/quickstart.md), [002 quickstart](../002-screen-display-rules/quickstart.md)

## 준비

- Java 21
- Maven
- 시작 관리자 비밀번호를 환경값 `ADMIN_INITIAL_PASSWORD`에 넣는다. 이 값을 명세, 설정 파일, 로그에 적지 않는다.

## 확인 명령

구현이 들어온 뒤 저장소 루트에서 다음을 실행한다.

```bash
mvn test
```

`mvn test`는 001·002의 기존 테스트와 003의 창 테스트를 함께 통과해야 한다. 003 테스트 이름은 `s003Fr00N_`으로 시작하고, 검증하는 003 요구사항 번호를 이름에 남긴다. 실패하면 구현을 명세에 맞게 고친 뒤 같은 명령을 다시 실행한다.

## 시나리오

1. 탈퇴, 상태 변경, 권한 변경 폼만 계약의 질문 문장을 가진다. 로그인, 가입, 수정, 비밀번호 변경, 로그아웃, 검색에는 그 질문이 없다. FR-002, FR-003, FR-004, FR-007.
2. 각 성공 한 건마다 계약의 알림 문장이 한 번 보이고, 그 문장에 비밀번호가 없다. 알림의 확인은 같은 저장을 반복하지 않는다. FR-005, FR-006, FR-009.
3. 가입·수정·비밀번호 변경의 입력 실패, 로그인 실패, 로그아웃, 검색에는 알림 창과 확인 창이 열리지 않는다. 실패 코드는 해당 묶음 위에만 있다. FR-007, FR-011.
4. 빈 비밀번호로 탈퇴를 눌러도 확인 창이 먼저 뜬다. 취소하면 실패 코드가 없고 입력은 유지되며 상태는 그대로이다. 확인 뒤 비밀번호가 틀리면 성공 알림 없이 탈퇴 묶음 위에만 실패 코드가 있다. FR-002, FR-008.
5. 마지막 ACTIVE 관리자의 탈퇴나 상태·권한 변경은 확인 뒤에도 거부되고, 성공 알림이 없으며 계정은 ACTIVE 관리자로 남는다. FR-008, FR-010.
6. 익명으로 `/dialogs.js`를 읽으면 200이다. 그 밖의 보호 화면 거부는 001과 같다. FR-005, FR-010.

## 브라우저

자동 테스트가 문장과 대상을 확인한 뒤, 브라우저에서 같은 서버를 연다.

```bash
mvn spring-boot:run
```

1. 내 정보에서 탈퇴 비밀번호를 비운 채 탈퇴를 누른다. 확인 창이 실패 코드보다 먼저 보이면 FR-002의 빈 입력 순서는 충족이다. 취소를 눌렀을 때 화면이 그대로이면 SC-001의 취소는 충족이다.
2. 가입, 수정, 비밀번호 변경, 탈퇴, 상태 변경, 권한 변경을 한 번씩 성공시킨다. 각 알림 문장이 계약과 같고 확인 후 같은 문장이 다시 저장을 일으키지 않으면 SC-002와 SC-005는 충족이다.
3. 창 가로를 390px로 두고 확인 창을 연다. 페이지 전체를 가로로 밀지 않고 `확인`과 `취소`에 도달하면 좁은 창 조건은 충족이다.
