# Dialog Contract: 알림 창과 확인 창

라우트, 허용 역할, 입력 검증, 오류 코드, 화면 순서는 [001 웹 계약](../../001-user-management/contracts/web.md)과 [002 화면 계약](../../002-screen-display-rules/contracts/screens.md)을 따른다. 이 계약은 어느 요청 앞에 확인 창을 열고, 어느 성공에 알림 창을 여는지만 정한다.

공통:

- 알림 창은 문장 하나와 `확인` 버튼 하나만 가진다. 버튼은 창만 닫는다.
- 확인 창은 질문 하나와 `확인`, `취소` 버튼만 가진다.
- 창이 열려 있는 동안 뒤 화면의 다른 동작은 진행되지 않는다. 창은 한 번에 하나만 연다.
- 창 문장에 비밀번호 원문을 넣지 않는다.
- 실패 코드는 002와 같이 실패한 폼의 입력칸 바로 위에만 보인다. 창 안에 코드를 반복하지 않는다.
- 가로 390px에서 열려 있는 창의 `확인` 또는 `취소`에 페이지 전체를 가로로 밀지 않고 도달한다.

## 확인 창

요청을 보내기 전에 연다. 입력이 비어 있거나 서버가 나중에 거부해도 먼저 연다. 취소는 요청을 만들지 않는다.

| 폼 | 질문 |
| --- | --- |
| 회원탈퇴 | 탈퇴하면 이 계정으로 다시 로그인할 수 없습니다. 탈퇴할까요? |
| 상태 변경 | 이 사용자의 상태를 변경할까요? |
| 권한 변경 | 이 사용자의 권한을 변경할까요? |

다음 폼에는 확인 속성을 두지 않는다. 로그인, 회원가입, 이름·이메일 수정, 비밀번호 변경, 로그아웃, 검색, 페이지 이동, 화면 링크.

## 알림 창

저장이 성공했을 때만 `notice`로 연다. 닫은 뒤의 화면과 저장 결과는 001의 성공 결과와 같다.

| 성공 | notice | 닫은 뒤 |
| --- | --- | --- |
| 가입 | 가입되었습니다. | 로그인 화면. 방문자 본인은 로그인되지 않음 |
| 이름·이메일 수정 | 회원정보를 수정했습니다. | 내 정보. 바뀐 이름과 이메일이 보임 |
| 비밀번호 변경 | 비밀번호를 변경했습니다. | 내 정보. 로그인 상태 유지 |
| 탈퇴 | 탈퇴했습니다. | 로그인 화면. 로그인 상태 종료 |
| 상태 변경 | 상태를 변경했습니다. | 그 사용자 상세. 알림은 요청한 관리자에게만 |
| 권한 변경 | 권한을 변경했습니다. | 그 사용자 상세. 대상의 로그인 상태는 유지 |

거부, 로그인 성공, 로그인 실패, 로그아웃, 검색, 화면 이동에는 알림 창을 열지 않는다.

## 정적 스크립트

`GET /dialogs.js`는 로그인하지 않아도 200으로 읽을 수 있다. 이 파일 공개 외의 인증·인가 규칙은 001과 같다.
