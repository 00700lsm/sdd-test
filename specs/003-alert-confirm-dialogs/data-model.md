# Data Model: 알림 창과 확인 창

저장 엔티티는 추가하거나 바꾸지 않는다. 필드, 유일 제약, 상태 전이는 [001 데이터 모델](../001-user-management/data-model.md)을 그대로 따른다. 아래는 화면에만 있는 구조이다.

## 확인 창

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| 대상 | 예 | 회원탈퇴, 상태 변경, 권한 변경 중 하나. 다른 폼에는 붙이지 않는다. |
| 질문 | 예 | 대상마다 하나. 탈퇴는 "탈퇴하면 이 계정으로 다시 로그인할 수 없습니다. 탈퇴할까요?", 상태는 "이 사용자의 상태를 변경할까요?", 권한은 "이 사용자의 권한을 변경할까요?" |
| 확인 | 예 | 그 폼의 기존 규칙을 한 번 진행한다. |
| 취소 | 예 | 창만 닫는다. 검증과 저장을 하지 않고 입력값을 유지한다. |

입력이 비어 있거나 나중에 거부되어도 버튼을 누르는 즉시 연다. 한 번에 하나의 창만 연다. 문장에 비밀번호 원문을 넣지 않는다.

## 알림 창

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| notice | 예 | 성공한 동작의 고정 문장 하나. 사용자 입력을 포함하지 않는다. |
| 확인 | 예 | 창만 닫는다. 같은 저장을 다시 실행하지 않는다. |

문장:

| 성공한 동작 | notice |
| --- | --- |
| 가입 | 가입되었습니다. |
| 이름·이메일 수정 | 회원정보를 수정했습니다. |
| 비밀번호 변경 | 비밀번호를 변경했습니다. |
| 탈퇴 | 탈퇴했습니다. |
| 상태 변경 | 상태를 변경했습니다. |
| 권한 변경 | 권한을 변경했습니다. |

실패, 로그인, 로그아웃, 검색, 화면 이동에는 `notice`를 두지 않는다. 상태·권한 알림은 그 변경을 실행한 관리자의 상세 응답에만 둔다.

## 상태 전이

없다. 확인을 누른 뒤의 수락과 거부는 001과 같다. 취소는 전이를 시작하지 않는다.
