# Research: 사용자 관리

## Decision: Java 21 + Spring Boot 4.1.1 단일 웹 애플리케이션

**Rationale**: 이 PoC는 화면 디자인보다 검증, 권한, 세션 무효화, 추적성을 확인한다. 2026-08-20에 배포된 Spring Boot 4.1.1은 현재 안정 버전이며 Spring Security 7.1.1을 포함한다. Java 21은 그 기준선에서 쓰는 현재 LTS이다. 서버에서 HTML 폼을 처리하면 화면과 검증 경계가 하나이고, 프론트엔드와 백엔드를 나누지 않아도 된다.

**Alternatives considered**:

- SPA와 JSON API를 분리한다. 시각 디자인이 범위 밖인데 전달 경로가 두 개가 된다.
- 경량 스크립트 서버. SI/SM에서 권한과 세션을 다시 검증하는 기본 구조와 거리가 있다.

## Decision: 서버 세션, 요청마다 계정 재조회

**Rationale**: 명세는 로그인 자동 만료를 두지 않고, 로그아웃·탈퇴·INACTIVE에서 로그인 상태를 끝낸다. 권한 변경은 세션을 유지한 채 다음 보호 요청부터 적용한다. 로그인 토큰에 권한을 고정하면 이 구분이 깨진다. HTTP 세션을 쓰고, 보호 요청마다 저장소의 상태와 권한을 다시 읽는다. INACTIVE 또는 탈퇴로 바꿀 때는 그 아이디의 진행 중인 세션을 즉시 만료한다.

**Alternatives considered**:

- 로그인 시점에 권한을 담은 서명 토큰. 만료 전에는 이전 권한이 남는다. 명세의 즉시 반영과 맞지 않는다.
- 상태만 다음 로그인부터 적용. 이미 기각된 선택이다.

## Decision: BCrypt 비밀번호 해시

**Rationale**: BCrypt는 솔트를 포함한 일방향 해시이다. 비교는 해시로만 하고, 원문은 컬럼, 로그, 응답, 오류에 넣지 않는다. 가역 암호화는 쓰지 않는다.

**Alternatives considered**:

- Argon2. 동등한 선택이나, 이 PoC의 기본 보안 구성이 BCrypt를 바로 제공한다.
- SHA-256 단일 해시. 비밀번호 저장 방식으로 부족하다.

## Decision: H2와 데이터베이스 유일 제약

**Rationale**: 외부 데이터베이스 없이 가입, 중복, 탈퇴 보존, 목록 정렬을 검증할 수 있다. 아이디와 이메일은 소문자로 저장하고 유일 제약으로 막는다. 동시에 같은 값으로 가입하면 제약 위반으로 하나만 저장되고, 실패한 쪽은 중복으로 응답한다. 사용자 행을 지우는 연산은 두지 않는다.

**Alternatives considered**:

- PostgreSQL. 운영형 저장소로는 맞지만, 이 PoC의 성공 기준은 동작과 추적성이다.
- 메모리 맵. 유일 제약과 탈퇴 후 재조회를 저장소 계약으로 남기기 어렵다.

## Decision: 시작 관리자 시드

**Rationale**: 아이디 `admin`, 이름 `관리자`, 이메일 `admin@example.com`, 권한 ADMIN, 상태 ACTIVE를 시작 시 없으면 만든다. 비밀번호는 환경값 `ADMIN_INITIAL_PASSWORD`로만 받고 명세, 설정 파일, 로그에 적지 않는다. 이미 계정이 있으면 환경값이 없어도 기동한다. 공개 가입으로 이 아이디를 만들지 못한다.

**Alternatives considered**:

- 첫 가입자를 관리자로 승격. 가입 결과가 항상 USER라는 명세와 충돌한다.
- 비밀번호를 저장소 예시에 고정. 평문 비밀번호를 산출물에 남긴다.

## Decision: 실패는 항목 코드로 모두 반환

**Rationale**: 한 요청의 실패 항목과 이유를 한 번에 돌려준다. 화면 문구는 코드에 대응하는 한국어이고, 테스트는 문구가 아니라 코드로 항목을 구분한다. 로그인 실패는 원인과 관계없이 `login.failed` 하나만 반환한다.

**Alternatives considered**:

- 첫 번째 실패만 반환. 이미 기각된 선택이다.
- 자유 문장만 비교. 문구 변경이 추적 테스트를 깨뜨린다.

## Decision: 목록과 검색은 1부터 시작하는 20건 페이지

**Rationale**: 조건으로 거른 뒤 가입 시각 내림차순으로 페이지를 나눈다. 번호는 1부터이고 크기는 20으로 고정한다. 범위를 넘는 다음 페이지 요청은 마지막 페이지를 유지한다. 검색어는 아이디, 이름, 이메일에 대소문자 구분 없이 포함되면 일치한다. 빈 검색어는 같은 조건의 목록이다.

**Alternatives considered**:

- 한 번에 전량 반환. 이미 기각된 선택이다.
- 호출자가 페이지 크기를 지정. 명세의 20명 단위와 어긋난다.
