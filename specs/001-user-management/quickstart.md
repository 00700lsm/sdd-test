# Quickstart: 사용자 관리

설계 확인용 실행 절차이다. 구현 코드와 테스트 본문은 `tasks.md` 이후의 구현 단계에서 만든다.

관련 계약: [contracts/web.md](contracts/web.md)

관련 모델: [data-model.md](data-model.md)

## 준비

- Java 21
- Maven
- 시작 관리자 비밀번호를 환경값 `ADMIN_INITIAL_PASSWORD`에 넣는다. 8–64자이고 아이디 `admin`과 달라야 한다. 이 값을 명세, 설정 파일, 로그에 적지 않는다.

## 확인 명령

구현이 들어온 뒤 저장소 루트에서 다음을 실행한다.

```bash
mvn test
mvn spring-boot:run
```

`mvn test`는 아래 시나리오의 성공 경로와 거부 경로를 포함해야 한다. 각 테스트 이름에 대응하는 FR 번호를 적는다. 실패하면 구현을 명세에 맞게 고친 뒤 같은 명령을 다시 실행한다.

## 시나리오

1. 규칙에 맞는 새 아이디로 가입하면 USER, ACTIVE가 된다. 비밀번호 원문은 응답에 없다. FR-001, FR-005, FR-006.
2. 그 계정으로 로그인하면 `/me`에서 자신의 이름과 이메일이 보인다. FR-007, FR-010.
3. 같은 아이디 또는 같은 이메일로 다시 가입하면 계정이 늘지 않고, 중복 항목 코드가 함께 반환된다. FR-002, FR-003, FR-004.
4. 로그아웃하면 `/me`가 로그인 필요 상태가 된다. 로그인하지 않은 로그아웃은 거부된다. FR-009, FR-017.
5. 이름과 이메일을 수정하면 이후 본인 조회에 반영된다. 다른 사용자의 관리자 상세, 목록, 상태 변경, 권한 변경은 거부되고 대상 정보를 돌려주지 않는다. FR-011, FR-015, FR-016.
6. 현재 비밀번호로 비밀번호를 바꾸면 이전 비밀번호 로그인은 실패하고 새 비밀번호 로그인은 성공한다. 현재 비밀번호 오류와 새 비밀번호 규칙 오류가 함께 있으면 두 코드가 한 응답에 있다. FR-012.
7. 현재 비밀번호로 탈퇴하면 상태가 WITHDRAWN이고 탈퇴 시각이 남으며 행 수는 줄지 않는다. 같은 자격 로그인은 `login.failed`이다. FR-013, FR-014, FR-024.
8. `admin`과 환경값 비밀번호로 로그인하면 기본 목록에 탈퇴 사용자가 없다. 탈퇴 포함과 아이디 지정 상세에는 탈퇴 시각이 있다. FR-018, FR-020, FR-026.
9. 검색어 하나가 이름 또는 이메일에만 포함되어도 그 사용자가 나온다. 빈 검색어는 목록과 같다. 21명이면 첫 페이지 20명, 다음 페이지 1명이고, 이전 페이지로 돌아오면 처음 20명이다. FR-018, FR-019.
10. 로그인한 사용자를 INACTIVE로 바꾸면 그 세션의 다음 보호 요청은 로그인 필요가 되고, 다시 ACTIVE로 바꾸면 로그인할 수 있다. 권한을 USER로 바꾸면 세션은 유지되고 다음 관리자 요청은 거부된다. FR-021, FR-022.
11. 유일한 ACTIVE ADMIN의 권한 변경, 비활성화, 탈퇴는 거부된다. FR-023.

화면의 색과 배치가 달라도 위 결과 데이터와 오류 코드가 맞으면 기능 확인은 성공이다. FR 대응은 [contracts/web.md](contracts/web.md)의 라우트 표를 기준으로 본다.
