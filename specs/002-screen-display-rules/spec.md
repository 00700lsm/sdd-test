# Feature Specification: 화면 배치와 표시

## Clarifications

### Session 2026-09-28

- Q: 내 정보 화면에서 비밀번호 변경만 실패하면, 실패 코드는 어디에 보이나요? → A: 실패한 그 폼의 입력칸 바로 위에만 보인다. 다른 폼 위나 화면 맨 위에는 같은 코드를 반복하지 않는다.
- Q: 넓은 창과 좁은 창은 어떤 크기로 확인하나요? → A: 넓은 창은 가로 1280px, 좁은 창은 가로 390px이다. 본문 열은 넓은 창에서 가운데에 있고 최대 폭은 640px이다. 좁은 창에서는 그 폭 안에서 창에 맞추며, 페이지 전체를 가로로 밀지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 모든 화면의 공통 배치 (Priority: P1)

로그인, 회원가입, 내 정보, 사용자 목록, 사용자 상세는 같은 읽기 순서를 따른다. 화면 이름이 먼저 보이고, 실패 이유는 입력칸보다 앞에 보이며, 각 입력칸은 자기 이름과 한 줄에 짝을 이룬다.

**Why this priority**: 다섯 화면이 제각각이면 이후 화면별 규칙을 검증할 기준이 없다.

**Independent Test**: 다섯 화면 중 아무거나 하나 열면, 제목으로 화면을 구분할 수 있고 입력칸과 그 이름이 짝으로 보인다.

**Acceptance Scenarios**:

1. **Given** 다섯 화면 중 하나, **When** 그 화면을 열면, **Then** 내용의 첫 항목은 그 화면의 이름인 제목이다. 제목은 로그인, 회원가입, 내 정보, 사용자 목록, 사용자 상세 중 해당 하나뿐이다. (FR-001)
2. **Given** 가로 1280px 창, **When** 폼이 있는 화면을 보면, **Then** 본문은 한 열로 가운데에 모이고 폭이 640px를 넘지 않는다. (FR-002)
3. **Given** 가로 390px 창, **When** 로그인 화면을 보면, **Then** 제목, 아이디, 비밀번호, 로그인 버튼 순서가 유지되고, 페이지 전체를 가로로 밀지 않아도 로그인 버튼에 도달한다. (FR-002, FR-003)
4. **Given** 한 폼에서 두 항목이 동시에 실패함, **When** 같은 화면이 다시 보이면, **Then** 두 실패 코드가 그 폼의 입력칸보다 위에 모두 보이고 서로 가리지 않는다. (FR-004)

### User Story 2 - 로그인과 회원가입 화면 (Priority: P2)

방문자는 로그인과 회원가입 화면에서 필요한 칸만 위에서 아래로 보고, 두 화면을 오갈 수 있다.

**Why this priority**: 계정을 만들고 들어가는 입구라서, 공통 배치 다음으로 순서가 고정되어야 한다.

**Independent Test**: 로그인 화면에서 회원가입으로 이동했다가 다시 로그인으로 돌아오고, 각 화면의 칸 순서가 아래 시나리오와 같다.

**Acceptance Scenarios**:

1. **Given** 로그인 화면, **When** 내용을 위에서 아래로 보면, **Then** 순서는 제목, 실패 표시, 아이디, 비밀번호, 로그인 버튼, 회원가입으로 가는 링크이다. (FR-005)
2. **Given** 회원가입 화면, **When** 내용을 위에서 아래로 보면, **Then** 순서는 제목, 실패 표시, 아이디, 비밀번호, 이름, 이메일, 가입 버튼, 로그인으로 가는 링크이다. (FR-006)
3. **Given** 회원가입이 실패해 같은 화면이 다시 보임, **When** 방문자가 화면을 보면, **Then** 아이디, 이름, 이메일은 입력했던 값이 남아 있고 비밀번호 칸은 비어 있으며 비밀번호 원문은 보이지 않는다. (FR-006, FR-007)
4. **Given** 로그인 화면, **When** 회원가입 링크를 선택하면, **Then** 회원가입 화면이 보인다. 회원가입 화면에서 로그인 링크를 선택하면 로그인 화면이 보인다. (FR-005, FR-006)

### User Story 3 - 내 정보 화면 (Priority: P2)

로그인한 사용자는 자신의 현재 정보를 먼저 읽고, 그 다음 이름·이메일 수정, 비밀번호 변경, 탈퇴, 로그아웃을 서로 다른 동작으로 구분해서 본다.

**Why this priority**: 탈퇴와 정보 수정이 한 덩어리로 보이면 잘못된 동작을 누르기 쉽다.

**Independent Test**: 내 정보 화면에서 요약, 수정, 비밀번호 변경, 탈퇴, 로그아웃이 서로 다른 묶음으로 위에서 아래로 보인다.

**Acceptance Scenarios**:

1. **Given** 로그인한 사용자, **When** 내 정보 화면을 보면, **Then** 순서는 제목, 읽기 전용 요약, 이름·이메일 수정, 비밀번호 변경, 회원탈퇴, 로그아웃이다. 실패 코드는 실패한 그 폼의 입력칸 바로 위에만 보인다. (FR-008)
2. **Given** 내 정보 화면, **When** 요약을 보면, **Then** 아이디, 이름, 이메일, 권한, 상태가 그 순서로 보이고 요약 안의 값은 그 자리에서 고칠 수 없다. (FR-008)
3. **Given** 내 정보 화면, **When** 이름·이메일 수정 묶음을 보면, **Then** 그 묶음에는 탈퇴 버튼과 로그아웃 버튼이 없다. 탈퇴 묶음은 비밀번호 변경 묶음보다 아래이고, 로그아웃은 탈퇴 묶음보다 아래이다. (FR-008, FR-009)
4. **Given** 로그인한 ADMIN, **When** 내 정보 화면의 맨 아래를 보면, **Then** 사용자 목록으로 가는 링크가 로그아웃보다 아래에 보인다. 로그인한 USER의 같은 위치에는 그 링크가 없다. (FR-010)

---

### User Story 4 - 관리자 목록과 상세 (Priority: P3)

ADMIN은 목록에서 사용자를 표로 비교하고, 한 명을 골라 상세로 들어가며, 상세에서 목록으로 돌아온다.

**Why this priority**: 목록과 상세는 관리자만 쓰므로, 방문자와 본인 화면의 배치가 정해진 뒤에 둔다.

**Independent Test**: ADMIN이 목록에서 한 아이디를 선택해 상세를 보고, 목록으로 돌아온 뒤 칸 순서와 빈 결과가 시나리오와 같다.

**Acceptance Scenarios**:

1. **Given** ADMIN과 한 명 이상의 목록 대상, **When** 사용자 목록을 보면, **Then** 순서는 제목, 검색 묶음, 현재 페이지 번호, 표, 이전·다음, 내 정보 링크이다. 검색 묶음의 순서는 검색어, 탈퇴 포함, 검색 버튼이다. 목록 조회의 실패 코드는 검색 묶음의 입력칸 바로 위에만 보인다. (FR-011)
2. **Given** 목록 표, **When** 열을 왼쪽에서 오른쪽으로 보면, **Then** 순서는 아이디, 이름, 이메일, 권한, 상태, 탈퇴 시각이다. 한 사용자는 한 행이다. (FR-012)
3. **Given** 탈퇴 시각이 없는 사용자 행, **When** 그 행의 탈퇴 시각 칸을 보면, **Then** 칸은 비어 있다. 탈퇴 시각이 있는 행은 그 시각을 그 칸에 보여 준다. (FR-012)
4. **Given** 조건에 맞는 사용자가 없음, **When** 목록을 보면, **Then** "결과 없음"이 보이고 사용자 행은 없다. (FR-013)
5. **Given** 이전 페이지가 없음, **When** 목록을 보면, **Then** 이전 링크는 보이지 않는다. 다음 페이지가 없으면 다음 링크는 보이지 않는다. (FR-011)
6. **Given** 목록의 한 사용자, **When** ADMIN이 그 행의 아이디를 선택하면, **Then** 그 사용자의 상세 화면이 보인다. 상세의 순서는 제목, 요약, 상태 변경 묶음, 권한 변경 묶음, 목록으로 가는 링크이다. 상태 변경 실패는 상태 묶음 바로 위에만, 권한 변경 실패는 권한 묶음 바로 위에만 보인다. (FR-014)
7. **Given** 상세 화면, **When** 요약을 보면, **Then** 아이디, 이름, 이메일, 권한, 상태가 그 순서로 보인다. 상태가 탈퇴인 경우에만 그 다음에 탈퇴 시각이 보인다. (FR-014)
8. **Given** 상세 화면, **When** 상태 변경 묶음과 권한 변경 묶음을 보면, **Then** 둘은 서로 다른 묶음이다. 상태 묶음은 ACTIVE와 INACTIVE만 고를 수 있고, 권한 묶음은 USER와 ADMIN만 고를 수 있다. (FR-015)

---

### Edge Cases

- 가로 390px 창에서 이름 50자와 이메일 254자는 잘리지 않고 해당 열 안에서 이어서 읽을 수 있다. 페이지 전체를 가로로 밀지 않는다.
- 실패 코드가 여러 개여도 나중에 온 코드가 앞의 코드를 지우거나 가리지 않는다.
- 목록이 20행이어도 열 이름은 표의 첫째 행에 남고, 이전·다음은 표 아래에 있다.
- 가로 390px 창에서 목록 표가 열 폭을 넘으면 표 영역만 가로로 움직일 수 있다. 제목과 검색 버튼은 페이지 전체의 가로 이동 없이 도달한다.
- 회원가입 실패 후 비밀번호 칸은 비어 있다. 로그인 실패 후에도 비밀번호 칸은 비어 있고, 입력했던 아이디는 남아 있다.
- USER가 내 정보 화면에 있을 때 사용자 목록 링크는 보이지 않는다. 링크 자리를 빈 제목으로 남기지 않는다.
- 상세의 대상이 탈퇴 사용자여도 요약과 탈퇴 시각은 보이고, 상태 변경 묶음과 권한 변경 묶음은 그대로 보인다. 거부 이유는 방금 제출한 그 묶음의 입력칸 바로 위에만 보인다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 로그인, 회원가입, 내 정보, 사용자 목록, 사용자 상세는 각각 하나의 제목으로 화면 이름을 먼저 보여야 한다. 제목 문구는 그 화면 이름과 같다.
- **FR-002**: 각 화면의 본문은 위에서 아래로 한 열이다. 넓은 창은 가로 1280px, 좁은 창은 가로 390px이다. 본문 열은 넓은 창에서 가운데에 있고 최대 폭은 640px이다. 좁은 창에서는 그 최대 폭 안에서 창에 맞추며, 페이지 전체를 가로로 밀지 않는다.
- **FR-003**: 각 입력 항목은 항목 이름과 입력칸이 한 줄로 짝을 이룬다. 한 줄에 서로 다른 입력칸을 나란히 두지 않는다. 폼의 주 동작 버튼은 그 폼의 입력칸들보다 뒤에 있다.
- **FR-004**: 실패 코드는 실패한 그 폼의 입력칸 바로 위에만 텍스트로 모두 보인다. 다른 폼 위나 화면 맨 위에 같은 코드를 반복하지 않는다. 코드끼리 겹치지 않는다. 비밀번호를 입력하는 동안 그 문자는 가려진다.
- **FR-005**: 로그인 화면의 순서는 제목, 실패 표시, 아이디, 비밀번호, 로그인 버튼, 회원가입 링크이다. 다른 계정 항목은 두지 않는다.
- **FR-006**: 회원가입 화면의 순서는 제목, 실패 표시, 아이디, 비밀번호, 이름, 이메일, 가입 버튼, 로그인 링크이다.
- **FR-007**: 실패로 다시 보여 주는 로그인·회원가입 화면에서 비밀번호 칸은 비어 있고 비밀번호 원문은 어디에도 보이지 않는다. 로그인 실패 시 아이디는 유지된다. 회원가입 실패 시 아이디, 이름, 이메일은 유지된다.
- **FR-008**: 내 정보 화면의 순서는 제목, 읽기 전용 요약, 이름·이메일 수정, 비밀번호 변경, 회원탈퇴, 로그아웃이다. 요약의 순서는 아이디, 이름, 이메일, 권한, 상태이며 그 자리에서 고칠 수 없다. 실패 코드는 실패한 수정, 비밀번호 변경, 탈퇴 묶음 바로 위에만 보인다.
- **FR-009**: 이름·이메일 수정, 비밀번호 변경, 회원탈퇴, 로그아웃은 서로 다른 동작 묶음이다. 한 묶음의 버튼이 다른 묶음의 항목을 함께 보내지 않도록 묶음이 나뉜다.
- **FR-010**: ADMIN의 내 정보 화면에서만 사용자 목록 링크가 로그아웃보다 아래에 보인다. USER에게는 그 링크가 보이지 않는다.
- **FR-011**: 사용자 목록의 순서는 제목, 검색 묶음, 현재 페이지 번호, 표 또는 빈 결과, 이전·다음, 내 정보 링크이다. 검색 묶음은 검색어, 탈퇴 포함, 검색 버튼 순서이다. 목록 조회의 실패 코드는 검색 묶음의 입력칸 바로 위에만 보인다. 이전 페이지가 없으면 이전 링크는 숨고, 다음 페이지가 없으면 다음 링크는 숨는다.
- **FR-012**: 목록 표의 열 순서는 아이디, 이름, 이메일, 권한, 상태, 탈퇴 시각이다. 한 사용자는 한 행이다. 탈퇴 시각이 없는 행의 그 칸은 비어 있다.
- **FR-013**: 보여줄 사용자가 없으면 "결과 없음"이 보이고 사용자 행은 없다.
- **FR-014**: 목록 행의 아이디를 선택하면 그 사용자의 상세로 이동한다. 상세의 순서는 제목, 요약, 상태 변경, 권한 변경, 목록 링크이다. 요약 순서는 아이디, 이름, 이메일, 권한, 상태이고, 탈퇴 상태일 때만 이어서 탈퇴 시각이 보인다. 상태 변경 실패는 상태 묶음 바로 위에만, 권한 변경 실패는 권한 묶음 바로 위에만 보인다.
- **FR-015**: 상세의 상태 변경과 권한 변경은 서로 다른 묶음이다. 상태에서 고를 수 있는 값은 ACTIVE와 INACTIVE뿐이고, 권한에서 고를 수 있는 값은 USER와 ADMIN뿐이다.
- **FR-016**: 이 기능은 기존 사용자 관리의 입력 검증, 권한, 상태 전이, 저장 결과를 바꾸지 않는다. 바꾸는 것은 같은 정보의 순서, 묶음, 보이는 조건뿐이다.

### Key Entities

- **화면**: 로그인, 회원가입, 내 정보, 사용자 목록, 사용자 상세 중 하나. 하나의 제목과 한 열의 내용을 가진다.
- **동작 묶음**: 함께 제출되는 입력칸과 버튼. 다른 묶음의 버튼을 포함하지 않는다.
- **목록 행**: 사용자 한 명의 아이디, 이름, 이메일, 권한, 상태, 탈퇴 시각. 아이디는 그 사용자의 상세로 연결된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 다섯 화면 모두에서 검토자가 제목만 보고 화면 이름을 맞춘다. 다섯 화면 중 틀린 화면은 0이다.
- **SC-002**: 가로 1280px 창에서 폼 본문은 가운데에 있고 폭이 640px를 넘지 않는다. 가로 390px 창에서 로그인 버튼까지 페이지 전체를 가로로 밀지 않고 도달한다.
- **SC-003**: 한 폼의 실패가 두 개일 때, 두 코드가 입력칸보다 위에서 100% 함께 보인다.
- **SC-004**: 로그인과 회원가입은 각 한 번의 링크 선택으로 서로 이동한다. ADMIN은 내 정보에서 목록으로, 목록의 아이디에서 상세로, 상세에서 목록으로 각각 한 번에 이동한다.
- **SC-005**: 배치를 적용한 뒤에도 기존 사용자 관리의 성공·거부 결과와 오류 코드는 그대로이다. 이 기능이 바꾸는 것은 순서와 표시뿐이다.

## Assumptions

- 배치 설명의 말줄임은 추가 요구가 아니다. 대상 화면은 로그인, 회원가입, 내 정보, 사용자 목록, 사용자 상세뿐이다.
- 어떤 데이터가 보이고 누가 들어갈 수 있는지는 기존 사용자 관리 명세를 따른다. 이 명세는 그 정보를 어떤 순서로 묶어서 보여 줄지만 더한다.
- 색 팔레트, 로고, 일러스트, 특정 글꼴 이름은 정하지 않는다. 글자와 실패 코드는 배경과 구분되어 읽을 수 있으면 된다.
- 폼은 한 열이다. 대시보드나 여러 단 배치는 쓰지 않는다.
- 목록의 아이디를 눌러 상세로 가는 이동은 이 명세에서 새로 정한다. 상세로 가는 다른 경로는 만들지 않는다.
- 가로 390px 창에서 표만 영역 안에서 가로로 움직일 수 있다. 페이지 전체의 가로 이동으로 폼 버튼을 찾게 하지 않는다.
- 화면 문구는 한국어이다. 실패 이유는 기존 명세의 코드 그대로 보여 주고, 코드를 다른 문장으로 바꾸지 않는다.
