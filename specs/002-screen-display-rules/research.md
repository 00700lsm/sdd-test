# Research: 화면 배치와 표시

## Decision: 기존 Java 21 + Spring Boot 4.1.1 화면만 바꾼다

**Rationale**: 이 기능은 검증, 권한, 상태 전이, 저장 결과를 바꾸지 않는다. 001에서 쓰는 서버 렌더링 Thymeleaf, 세션, BCrypt, H2를 유지하고 새 프레임워크나 화면 저장소를 두지 않는다.

**Alternatives considered**:

- 프론트엔드 저장소를 분리한다. 같은 정보를 두 경로로 보여 주고, 001의 단일 검증 경계와 어긋난다.
- 컴포넌트 라이브러리로 다시 그린다. 색, 로고, 글꼴을 끌어와 명세의 범위 밖 결정이 된다.

## Decision: 공통 배치는 스타일시트 하나이다

**Rationale**: 다섯 화면이 같은 열 폭을 가져야 한다. `src/main/resources/static/layout.css`에만 배치 규칙을 둔다. 본문 열은 `width: 100%`, `max-width: 640px`, `margin-inline: auto`이다. 좁은 창은 `body` 기본 여백을 없애 가로 390px 안쪽에 맞춘다. 색, 로고, 글꼴 이름은 정하지 않는다. 각 템플릿은 이 스타일시트를 읽고, `viewport`를 장치 폭으로 둔다.

입력 항목은 이름과 칸이 한 행이고, 서로 다른 칸은 세로로만 쌓인다. 칸은 열 너비 안에서 줄어든다. 목록 표는 감싸는 영역만 `overflow-x: auto`이다. 이름과 이메일 칸은 줄바꿈되어 잘리지 않는다. 페이지 자체에는 가로 스크롤을 만들지 않는다.

**Alternatives considered**:

- 템플릿마다 인라인 스타일. 다섯 화면의 폭이 따로 바뀔 수 있다.
- 브라우저 드라이버를 추가해 1280px와 390px를 픽셀로 클릭한다. 이 PoC의 테스트는 MockMvc이고, 폭은 스타일시트 규칙으로 고정할 수 있다. 실제 창 확인은 quickstart에 남긴다.

## Decision: 실패 코드는 실패한 폼 안에만 둔다

**Rationale**: 여러 폼이 있는 화면에서 코드를 제목 아래에 두면 다른 폼의 실패처럼 보인다. 컨트롤러는 기존 실패 목록을 유지하고, 어떤 폼이 실패했는지만 `errorForm`으로 넘긴다. 값은 `profile`, `password`, `withdrawal`, `list`, `status`, `role`이다. 템플릿은 그 폼의 입력칸 바로 위에만 코드를 그린다. 로그인과 회원가입은 폼이 하나이므로 제목 다음, 아이디 칸 앞에 둔다. 코드 문자와 서버 검증은 001 그대로이다.

**Alternatives considered**:

- 화면 맨 위에 한 번 더 보여 준다. 명확화에서 기각된 선택이다.
- 서비스가 폼 이름을 알게 한다. 검증 결과에 화면 구조를 섞는다.

## Decision: 목록 아이디만 상세로 연결한다

**Rationale**: 상세로 가는 경로는 목록 행의 아이디 하나이다. 아이디 글자를 그 사용자의 `/admin/users/{loginId}` 링크로 만든다. 행의 다른 칸과 별도의 상세 버튼은 두지 않는다.

**Alternatives considered**:

- 행 전체를 링크로 만든다. 명세는 아이디 선택만 말한다.
- 아이디를 텍스트로 두고 다른 경로를 추가한다. 새 경로를 만들지 않는다는 가정과 충돌한다.

## Decision: 표시 테스트는 002 번호를 쓰고, 001 테스트는 유지한다

**Rationale**: 헌법 II는 테스트가 명세 항목을 식별할 것을 요구한다. 001 테스트 이름은 이미 `fr00N_`이다. 002 테스트는 `src/test/java/com/poc/usermanagement/display/`에 두고 이름을 `s002Fr00N_`으로 시작한다. MockMvc로 순서, 묶음, 코드 위치, 링크, 빈 결과를 확인한다. 스타일시트에 640px, 가운데 정렬, 표 영역 스크롤이 있는지도 확인한다. 기존 `mvn test`는 코드와 저장 결과가 그대로인지 회귀로 다시 실행한다.

**Alternatives considered**:

- 001 테스트 이름을 002 번호로 바꾼다. 기존 추적 연결이 끊긴다.
- 픽셀 측정을 자동화하지 않고 순서 테스트도 생략한다. 주요 기능의 성공·거부 확인이 비게 된다.
