# Quickstart: 화면 배치와 표시

설계 확인용 실행 절차이다. 구현 코드와 테스트 본문은 `tasks.md` 이후의 구현 단계에서 만든다.

관련 계약: [contracts/screens.md](contracts/screens.md)

관련 모델: [data-model.md](data-model.md)

기존 동작: [001 quickstart](../001-user-management/quickstart.md)

## 준비

- Java 21
- Maven
- 시작 관리자 비밀번호를 환경값 `ADMIN_INITIAL_PASSWORD`에 넣는다. 이 값을 명세, 설정 파일, 로그에 적지 않는다.

## 확인 명령

구현이 들어온 뒤 저장소 루트에서 다음을 실행한다.

```bash
mvn test
```

`mvn test`는 001의 기존 테스트와 002의 표시 테스트를 함께 통과해야 한다. 002 테스트 이름은 `s002Fr00N_`으로 시작하고, 검증하는 002 요구사항 번호를 이름에 남긴다. 실패하면 구현을 명세에 맞게 고친 뒤 같은 명령을 다시 실행한다.

## 시나리오

1. 로그인, 회원가입, 내 정보, 사용자 목록, 사용자 상세의 첫 제목이 각각 그 화면 이름과 같다. FR-001.
2. 스타일시트의 본문 열은 최대 640px이고 가운데 정렬이다. 표가 넘칠 때 움직이는 영역은 표 안쪽이다. FR-002.
3. 각 입력 이름은 자기 칸과 한 행이고, 버튼은 그 칸보다 뒤이다. 비밀번호 칸은 문자를 가린다. FR-003, FR-004.
4. 한 폼에서 두 항목이 실패하면 두 코드가 그 폼 안에 함께 있다. 비밀번호 변경만 실패하면 코드는 비밀번호 폼에만 있고 수정 폼과 탈퇴 폼에는 없다. FR-004, FR-008.
5. 로그인과 회원가입은 계약의 칸 순서이고, 한 번의 링크로 서로 이동한다. 실패 후 비밀번호 칸은 비어 있다. FR-005, FR-006, FR-007.
6. 내 정보는 요약, 수정, 비밀번호 변경, 탈퇴, 로그아웃 순서이다. USER에게는 사용자 목록 링크가 없고 ADMIN에게는 로그아웃 아래에 있다. FR-008, FR-009, FR-010.
7. 목록은 검색, 페이지 번호, 표, 이전·다음, 내 정보 순서이다. 아이디를 누르면 그 사용자 상세가 열린다. 결과가 없으면 `결과 없음`만 있다. 이전 또는 다음이 없으면 그 링크는 없다. FR-011, FR-012, FR-013, FR-014.
8. 상세의 상태 변경과 권한 변경은 서로 다른 폼이다. 상태 실패 코드는 상태 폼에만, 권한 실패 코드는 권한 폼에만 있다. 선택 값은 ACTIVE/INACTIVE와 USER/ADMIN뿐이다. FR-014, FR-015.
9. 위 표시를 바꾼 뒤에도 001 테스트의 성공·거부 결과와 오류 코드가 그대로 통과한다. FR-016.

## 창 크기

자동 테스트가 스타일시트 규칙을 확인한 뒤, 브라우저에서 같은 서버를 연다.

```bash
mvn spring-boot:run
```

1. 창 가로를 1280px로 두고 로그인 화면을 본다. 본문 열이 가운데에 있고 폭이 640px를 넘지 않으면 SC-002의 넓은 창은 충족이다.
2. 창 가로를 390px로 두고 로그인 버튼을 본다. 페이지 전체를 가로로 밀지 않고 버튼에 도달하면 SC-002의 좁은 창은 충족이다.
3. 같은 390px에서 사용자 목록을 본다. 제목과 검색 버튼은 페이지 가로 이동 없이 도달하고, 표만 영역 안에서 움직일 수 있으면 목록의 좁은 창 조건은 충족이다.
