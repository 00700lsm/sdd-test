# Data Model: 화면 배치와 표시

저장 엔티티는 추가하거나 바꾸지 않는다. 필드, 유일 제약, 상태 전이는 [001 데이터 모델](../001-user-management/data-model.md)을 그대로 따른다. 아래는 화면에만 있는 구조이다.

## 화면

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| 이름 | 예 | `로그인`, `회원가입`, `내 정보`, `사용자 목록`, `사용자 상세` 중 하나. 내용의 첫 제목과 같다. |
| 본문 열 | 예 | 위에서 아래로 하나. 최대 폭 640px, 넓은 창에서 가운데. 좁은 창은 가로 390px 안에 맞춘다. |

다섯 화면 밖에 배치 대상을 만들지 않는다.

## 동작 묶음

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| 대상 | 예 | 한 폼. 다른 묶음의 버튼을 포함하지 않는다. |
| 실패 코드 | 아니오 | 그 폼의 입력칸 바로 위에만 표시. 다른 폼이나 화면 맨 위에 반복하지 않는다. |
| errorForm | 조건부 | 실패했을 때만 `profile`, `password`, `withdrawal`, `list`, `status`, `role` 중 하나. |

내 정보의 묶음 순서는 읽기 전용 요약, 이름·이메일 수정, 비밀번호 변경, 회원탈퇴, 로그아웃이다. 요약 값은 그 자리에서 고치지 않는다. 상세의 상태 변경과 권한 변경은 서로 다른 묶음이다.

## 목록 행

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| 아이디 | 예 | 표시 텍스트이자 그 사용자 상세로의 유일한 링크. |
| 이름 | 예 | 50자도 칸 안에서 이어서 보인다. |
| 이메일 | 예 | 254자도 칸 안에서 이어서 보인다. |
| 권한 | 예 | 저장값 그대로. |
| 상태 | 예 | 저장값 그대로. |
| 탈퇴 시각 | 아니오 | 값이 없으면 칸이 비고, 있으면 그 칸에 보인다. 별도 표시 형식은 정하지 않는다. |

열 순서는 아이디, 이름, 이메일, 권한, 상태, 탈퇴 시각이다. 한 사용자는 한 행이다. 행이 없으면 `결과 없음`만 보이고 사용자 행은 없다.

## 상태 전이

없다. 상태와 권한 값이 바뀌는 조건은 001과 같다.
