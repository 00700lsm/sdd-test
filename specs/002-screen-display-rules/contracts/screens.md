# Screen Contract: 화면 배치와 표시

라우트, 허용 역할, 입력 검증, 오류 코드는 [001 웹 계약](../../001-user-management/contracts/web.md)을 따른다. 이 계약은 같은 응답을 어떤 순서로 보여 주는지만 정한다. 코드 문자는 바꾸지 않는다.

공통:

- 내용의 첫 요소는 화면 이름과 같은 `h1` 하나이다.
- 본문은 한 열이다. 최대 폭은 640px이고 가로 1280px 창에서는 가운데에 있다. 가로 390px 창에서는 그 폭 안에서 창에 맞추며 페이지 전체를 가로로 밀지 않는다.
- 입력 항목은 항목 이름과 칸이 한 행이다. 한 행에 서로 다른 입력칸을 두지 않는다. 주 동작 버튼은 그 폼의 칸보다 뒤이다.
- 비밀번호 칸은 입력 중 문자를 가린다. 실패 후 그 칸은 비어 있고 원문은 응답에 없다.
- 실패 코드는 실패한 폼의 입력칸 바로 위에만 텍스트로 모두 보인다.

## 로그인

순서: 제목 `로그인`, 실패 표시, 아이디, 비밀번호, 로그인 버튼, 회원가입 링크.

다른 계정 항목은 없다. 실패 시 아이디는 유지된다. 회원가입 링크는 `/signup`이다.

## 회원가입

순서: 제목 `회원가입`, 실패 표시, 아이디, 비밀번호, 이름, 이메일, 가입 버튼, 로그인 링크.

실패 시 아이디, 이름, 이메일은 유지되고 비밀번호는 비어 있다. 로그인 링크는 `/login`이다.

## 내 정보

순서: 제목 `내 정보`, 읽기 전용 요약, 이름·이메일 수정, 비밀번호 변경, 회원탈퇴, 로그아웃.

요약 순서는 아이디, 이름, 이메일, 권한, 상태이다. 수정 폼에는 탈퇴와 로그아웃이 없다. ADMIN만 로그아웃 아래에 `사용자 목록` 링크(`/admin/users`)가 있다. USER에게는 그 링크가 없다.

| errorForm | 코드가 보이는 위치 |
| --- | --- |
| `profile` | 이름·이메일 칸 바로 위 |
| `password` | 현재 비밀번호 칸 바로 위 |
| `withdrawal` | 탈퇴용 현재 비밀번호 칸 바로 위 |

## 사용자 목록

순서: 제목 `사용자 목록`, 검색 묶음, 현재 페이지 번호, 표 또는 빈 결과, 이전·다음, `내 정보` 링크.

검색 묶음의 보이는 순서는 검색어, 탈퇴 포함, 검색 버튼이다. 목록 조회의 실패 코드(`page.invalid`, `withdrawn.invalid`)는 검색 칸 바로 위에만 보인다. `errorForm`은 `list`이다.

표의 첫 행은 열 이름이다. 사용자 행의 아이디만 `/admin/users/{loginId}`로 이동한다. 탈퇴 시각이 없는 칸은 비어 있다. 행이 없으면 `결과 없음`이 보이고 사용자 행은 없다. 이전 페이지가 없으면 `이전`은 숨고, 다음 페이지가 없으면 `다음`은 숨는다. 가로 390px에서 표가 넘치면 표 영역만 가로로 움직인다.

## 사용자 상세

순서: 제목 `사용자 상세`, 요약, 상태 변경, 권한 변경, 목록 링크.

요약 순서는 아이디, 이름, 이메일, 권한, 상태이다. 상태가 탈퇴일 때만 이어서 탈퇴 시각이 보인다. 상태 묶음에서 고를 수 있는 값은 `ACTIVE`, `INACTIVE`뿐이다. 권한 묶음에서 고를 수 있는 값은 `USER`, `ADMIN`뿐이다. 두 묶음은 서로 다른 폼이다. 목록 링크는 `/admin/users`이다.

| errorForm | 코드가 보이는 위치 |
| --- | --- |
| `status` | 상태 칸 바로 위 |
| `role` | 권한 칸 바로 위 |

탈퇴 사용자여도 두 묶음은 보인다. 거부 코드는 방금 제출한 묶음 바로 위에만 있다.
